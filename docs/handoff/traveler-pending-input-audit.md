8 November 2026. **QUEST-ANSWER-PENDING-01** (`quest-question-pending-input-result-attribution-20261108-0813`) and **ITINERARY-DAY-TITLE-STATE-01** (`itinerary-day-title-save-draft-loss-before-ack-20261108-0813`) were reported by source inspection at `21e5610`. These were source-only findings; no original native/API baseline reproduction was provided.

## Quest input and results

Previously only Submit was disabled while an answer request was pending. Radio/text input could change to B while the response for A was displayed. Input controls now disable during the session's busy state and keep the submitted value visible. Editing the draft after a response hides that response when its submitted value differs from the new draft.

The existing Session captures the participation/activity/input attribution alongside its existing immutable request context before sending. Native identity projects a submitted value/result only for the matching participation and activity. A result for another activity or a logged-out generation cannot populate the current answer UI. Same-reader revisits retain the matching attribution. Compose answer state is keyed by actor generation, participation and activity. This adds session memory attribution, with no transport payload, intent key, attempt/reward policy, journal or automatic replay change. Existing input `rememberSaveable` behavior is retained with stronger context keys; the new Session attribution is not serialized.

Three new MockEngine host cases exercise the production Session and NativeTravelerIdentity: gated A and explicit B with distinct existing intent keys; same-reader revisit versus another activity; existing-key explicit retry and a late response after logout. Five native cases use production Compose/ViewModel with synthetic identity projections: radio/text attempts to edit B while A is busy, incorrect A then edited/explicit B, correct final-activity acknowledgement, Back/revisit without replay, and actor-late response. The final-activity UI fixture proves acknowledgement timing, not live reward issuance or provider attestation.

## Day title draft ownership

The previous dialog discarded its local value immediately on Save, including when consent preflight failed before the title repository was called. The ViewModel now retains values per itinerary/day. The editor survives preflight errors, Legal review/Back, validation, throttle and uncertain responses. Save captures the itinerary/day/value before asynchronous work. Only the matching acknowledged draft or an explicit Cancel/dismiss removes it; actor reset erases retained drafts. Pending Save freezes input and prevents duplicate submission. A late old-actor callback cannot close or refresh a new actor's editor.

The existing metadata write and consent gate remain in use. Refresh, GET and returning from Legal do not replay Save. Error/retry is visible inside the dialog, where the user can still read/correct the retained value. Unknown results retain the existing uncertainty warning; existing Retry-After deadlines guard explicit retry. No rollback, successful write or definite failure is invented for an unknown result.

Seven host cases cover NetworkError/503 preflight with zero title repository calls, one explicit Ready retry, Legal/read Back without replay, 422/429/unknown, pending duplicate/input guards, Cancel and separate itinerary/day origins, and late preflight/acknowledgement across actor reset. Six native dialog cases cover preflight NetworkError/503, Cancel, Legal Back, validation, unknown and Retry-After. These title assertions are at the repository boundary; they are not a new live HTTP integration claim.
