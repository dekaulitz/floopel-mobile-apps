# Open Trip and Community search after reader Back

8 November 2026. **COMMUNITY-SEARCH-BACK-01** (`trip-public-plan-search-back-query-loss-20261108-0713`) was reported by read-only source inspection at `fb3fc9b`. The original finding had no native/API baseline reproduction. The earlier Catalog correction covered Explorer and Spot archives; these additional consumers use different repositories.

Opening a Trip or public itinerary reader reset the shared search field. Back then requested an unfiltered list. The ViewModel now remembers the query in session memory for each complete Open Trip origin route, including its optional location, and separately for Community public itineraries and Community Open Trip. It restores the matching value before refreshing on Back. This keeps the field, filtered request and results consistent without adding an API contract or persistent search storage.

Explicit clear stays clear. Community tab selection and main navigation retain their existing empty-query reset, including when a previously searched origin is entered again and its default result is opened without typing. Community tab selection cancels the outgoing debounce and public-plan/Open Trip/catalog reads, so a late cancelled result cannot repopulate another tab. Actor/generation changes erase the retained queries. Search text is not serialized into saved navigation.

The existing shared search fields, cards and navigation are reused. Figma [5:326](https://www.figma.com/design/ifQcOxbjGTXw9aNH2JGl9g/Floopel-Mobile?node-id=5-326), [12:305](https://www.figma.com/design/ifQcOxbjGTXw9aNH2JGl9g/Floopel-Mobile?node-id=12-305) and [316:5228](https://www.figma.com/design/ifQcOxbjGTXw9aNH2JGl9g/Floopel-Mobile?node-id=316-5228) provide journey context; this state correction introduces no layout, artwork, endpoint, provider or business policy change. Collection visual work remains documented in [its existing audit](traveler-collection-audit.md).

## Limits and restoration

New search scenarios use isolated domain repository fixtures; live search API integration is **NOT_RUN** here. The captures establish bound state in the existing UI, not whole-app Figma acceptance. Queries remain in session memory; process-death persistence is not claimed. iOS compilation/native UI require Mac/Xcode and remain **NOT_RUN**, as do TalkBack/VoiceOver, physical device and release checks.

The existing real session on 5580 is returned through read-only ngrok navigation to the public Collection reader, with five-second manual pauses. No live business write, account/database reset, notification acknowledgement, admission/publication action or device clock change is performed. Emulator size/density/font overrides are restored after testing.

Foreign `.gitignore` and Android `styles.xml` edits are byte-for-byte unchanged and excluded from the commit. The local style bytes participate in compilation and are recorded in the source/APK freeze. That freeze describes local execution provenance, not an assertion that a portable checkout reproduces excluded edits.
